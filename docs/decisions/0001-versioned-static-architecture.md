# 0001. 버전별 정적 브로슈어 구조

- 상태: 채택
- 결정일: 2026-07-31

## 왜 React/Vue를 사용하지 않았는가

이 프로젝트는 복잡한 애플리케이션 상태보다 문구, 이미지, 섹션 순서와 공개 당시 디자인을 보존하는 일이 중요하다. UI 프레임워크는 현재 규모에서 런타임과 추상화를 늘리고, 오래된 화면이 최신 공통 컴포넌트 변경에 영향을 받을 가능성도 높인다. DOM API와 작은 TypeScript 모듈이면 필요한 라우팅과 목록 생성을 충분히 구현할 수 있다.

## 왜 Vite + TypeScript인가

Vite는 개발 서버와 정적 빌드 구성이 작고 빠르며, 여러 HTML 진입점을 이용해 `/`, `/archive/`, `/v0.4/`를 실제 정적 경로로 만들 수 있다. TypeScript는 버전 메타데이터와 registry 함수의 계약을 명확히 해 새 버전을 추가할 때 누락을 일찍 발견하게 한다.

## 왜 과거 버전을 독립 경로로 보존하는가

과거 버전은 최신 데이터로 재구성한 화면이 아니라 공개 당시의 기록이다. 버전별 콘텐츠, 이미지, 스타일, 인터랙션을 독립 폴더와 스코프된 CSS로 두면 이후 공통 디자인이 바뀌어도 공개 당시 모습이 변하지 않는다. 각 경로는 직접 링크하거나 여행 후 실제 기록과 연결하기도 쉽다.

## 왜 Git 태그와 웹 버전 경로를 함께 사용하는가

웹 경로는 누구나 브라우저에서 과거 화면을 열어보게 한다. Git 태그는 소스, 설정, 문서까지 포함한 공개 시점의 전체 코드 상태를 재현하게 한다. 둘은 역할이 다르므로 함께 사용한다. 공개 태그는 불변 기록으로 취급하며 생성 후 수정하거나 재지정하지 않는다.
